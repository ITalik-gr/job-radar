# Job Radar

Локальний інструмент для пошуку роботи. Правила і межі проєкту: `CLAUDE.md`.

Розрахований на одного власника: своя база, своя пошта, свій ключ моделі. Якщо ти
клонував цей репо собі, почни з [FORK.md](FORK.md): там список того, що треба
переписати під себе, і що станеться, якщо цього не зробити.

## Два режими

**Задеплоєний воркер.** Адреса в кожного своя. Перший вхід з токеном:
`https://<твій-воркер>/?token=<RADAR_TOKEN>`, далі токен живе в браузері.

| режим | коли | як |
| --- | --- | --- |
| локально | розробка, дебаг адаптерів | `pnpm start` плюс `pnpm dev:web` |
| Cloudflare | щоденне користування, доступ з телефона, cron без ноута | `pnpm deploy`, деталі в `DEPLOY.md` |

Код один і той самий: Hono працює і в Node, і на Workers, схема Drizzle однакова для SQLite і D1.
Нативний драйвер `better-sqlite3` живе окремо в `db/client.node.ts`, щоб не потрапляти в бандл воркера.

## Швидкий старт

```bash
pnpm install
cp .env.example .env        # вписати ANTHROPIC_API_KEY і USER_AGENT_CONTACT
pnpm start                  # міграції, API на :3000, планувальник
pnpm dev:web                # інтерфейс на :5173, в іншому терміналі
```

Далі відкрити `http://localhost:5173`. Якщо база порожня, наповнити її можна так:

```bash
pnpm cli import:csv imports/seed-companies.csv   # 10 компаній з відомими ATS
pnpm cli source:sync greenhouse                  # забрати вакансії і класифікувати
pnpm cli source:sync ashby
pnpm cli catalog:dou -n 40 --business "Tech Product,Startup"
pnpm cli discover -n 25                          # career-сторінки для решти
pnpm cli queue                                   # те саме, що бачить веб
```

## Збирач каталогів: розширення Chrome

Качати сторінки руками не треба. `extension/` це розширення: `chrome://extensions`,
режим розробника, "Завантажити розпаковане", вибрати теку `extension`. Далі просто гортаєш
каталог, кожна відкрита сторінка збирається сама. Деталі: `extension/README.md`.

**Одразу після встановлення відкрий попап і впиши свою адресу API**, наприклад
`http://localhost:3000`, а якщо заданий `RADAR_TOKEN`, то і його. У дефолтах зараз
стоїть адреса воркера автора, і поки її не змінити, зібрані тобою компанії підуть
не тобі, причому мовчки: попап покаже "на звʼязку" і зростаючі лічильники, бо чужий
сервер справді відповідає. Це відома проблема, вона описана в [FORK.md](FORK.md).

Підтримані каталоги: Clutch, GoodFirms, DesignRush, Sortlist, The Manifest, UpCity,
TechBehemoths, DOU. Незнайомий каталог розбирається через JSON-LD.

Альтернатива без встановлення: `pnpm cli bookmarklet` друкує код закладки з тією ж логікою.

```
Job Radar: на сторінці 80, з доменом 79
нових 12, оновлено 67, без домену 1
```

Чому саме так, а не скрейпер: Clutch, GoodFirms, DesignRush, Sortlist і TechBehemoths стоять
за Cloudflare і віддають челендж навіть на `robots.txt`. Обходити його заборонено правилом 4
з `CLAUDE.md`. Але сторінку, яку ти й так відкрив у своєму браузері, розбирає сам браузер,
і нічого обходити не треба. Збирач знає розмітку карток Clutch і подібних, а якщо не впізнав,
пробує JSON-LD `ItemList`, який віддає більшість каталогів.

## Каталоги компаній

| джерело | режим | чому так |
| --- | --- | --- |
| DOU | автоматично, `catalog:dou` | відкритий HTML, `robots.txt` дозволяє |
| Clutch | ручний імпорт збережених сторінок | Cloudflare з бот-детектом |
| TechBehemoths | збирач у браузері | віддає Cloudflare-челендж навіть на `robots.txt` |
| GoodFirms, DesignRush, Sortlist, The Manifest, UpCity | збирач у браузері | те саме, 403 на будь-який запит |
| Wadline, Awwwards | поки ні | дані рендеряться клієнтом, домену компанії в HTML немає |

DOU показує по 20 компаній на сторінку, а кнопка "більше" це POST з CSRF-токеном. Замість
імітації сесії обходимо комбінації фільтрів (`business` і `domain`). Домен, розмір і місто
лежать на сторінці компанії, тому другий крок це обхід профілів з паузою в секунду.

Clutch ховає домен у параметрі `u` редиректу `r.clutch.co`. Якщо у файлі не розпізналось
жодної картки, це помилка в звіті, а не тихий нуль.

## Виявлення змін

- **ATS** віддають стабільні `external_id`, тому поява і закриття рахуються порівнянням
  множин id (`diffByExternalId`). Хешувати текст не треба.
- **Власні career-сторінки** проходять нормалізацію (`pipeline/normalize.ts`), блочний діф
  (`pipeline/diff.ts`) і запис знімка (`pipeline/snapshots.ts`), не більше пʼяти на компанію.

Фікстури для дифу: `fixtures/careers/acme-v1.html`, `acme-v1-noise.html` (той самий набір
вакансій, інші дати, лічильники, білд-хеші), `acme-v2.html` (мінус одна, плюс одна). Тест
вимагає, щоб шумова версія дала той самий хеш.

## Налаштування відбору

Усі списки і ваги лежать у `config/scoring.json`, код чіпати не треба. Файл перечитується
на льоту (не частіше разу на 5 секунд), після правки треба перерахувати рахунки:

```bash
pnpm cli score:recalc                  # перерахувати все за новими правилами
pnpm cli score:explain vacancy 123     # чому саме такий рахунок
pnpm cli score:explain company 45
```

Що там налаштовується:

| розділ | навіщо |
| --- | --- |
| `roleGate` | назва вакансії має бути інженерною. Без цього "Sr. Manager, Accounting" набирає балів з тексту про компанію, де згадані React і Next.js |
| `geo` | Київ, переїзд неможливий. "Remote (US)", "San Francisco, hybrid" і будь-яка локація з назвою місця без ознак віддаленості відсіюються, хай там що каже прапорець remote |
| `experience` | 5+ років це -4, 7+ це -8, лідська назва окремо |
| `stopWords` | технології і сфери, які не потрібні |
| `weights` | ваги технологій. Назва важить утричі, бали з тексту обмежені стелею `bodyCap` |
| `companies` | скоринг студій: розмір, послуги, стек сайту, країна, ставка |

## Скільки коштує модель

Класифікація на Haiku. Детерміновані фільтри (стоп-слова, роль, гео, розмір компанії)
працюють ДО виклику моделі, тому платимо лише за те, що має шанс потрапити в чергу.
Цифри, причини і що ще можна стиснути: `COSTS.md`.

## Класифікація і скоринг

1. Стоп-слова по короткому тексту блока, до будь-якої мережі
2. Довантаження сторінки вакансії, якщо блок коротший за 400 символів
3. Стоп-слова ще раз по повному тексту
4. LLM (`claude-haiku-4-5-20251001`), строгий JSON, Zod, один ретрай, далі `needs_review`
5. Детермінований скоринг у коді, `score = сума ваг + llm_relevance / 20`

Кеш у `llm_cache` за хешем тексту, який пішов у модель. Денна стеля у `LLM_DAILY_CALL_LIMIT`,
лічильник у `llm_usage`. Все, що нижче `SCORE_THRESHOLD`, лишається в базі, просто не
показується у черзі. Вакансії не видаляються ніколи, зниклі отримують `closed_at`.

## Інтерфейс

Сторінки: **Черга** (вакансії), **Студії** (кому запропонувати послуги), **Компанії**,
**Контакти**, **Статистика**, **Джерела**.

**Студії** це окрема черга від вакансій: невеликій агенції вакансія не потрібна, потрібен
підрядник. Рахунок рахується з розміру (10 до 49 найкраще), профілю послуг (web development
і дизайн у плюс, SEO і реклама в мінус), стеку сайту (React і Next.js у плюс, WordPress у мінус),
країни і ставки. Кнопка "Чому цей рахунок" показує розклад по балах.

Черга це зафіксований денний зріз у `queue_items`, а не запит на льоту: без фіксації нова
вакансія з вищим рахунком витісняє ту, яку ще не встигли подивитись. Рішення прибирає картку,
місце не переобирається до наступної доби. Показане за останні 30 днів у зріз не повертається.

## Телеграм і розклад

Телеграм тільки для алертів і нагадувань, керування станом там немає навмисно.

| коли | що |
| --- | --- |
| кожні 6 годин | ATS і RSS, докласифікація, алерт про score 12+, алерт про поламані джерела |
| щопонеділка 04:00 | каталог DOU |
| щовівторка 05:00 | discovery career-сторінок |
| щодня 10:00 | дайджест черги |
| щодня 18:00 | нагадування про фолоу-апи без відповіді понад 7 днів |

Бот не може написати першим: спершу треба відкрити чат з ним і натиснути Start,
інакше Telegram віддає `chat not found`. Перевірка: `pnpm cli notify:check`.

Команди бота (тільки читання, дії робляться у вебі): `/help` опис усієї системи, `/status`
що зараз у базі, `/queue` топ карток, `/followups` кому час нагадати. Полінг вимикається
змінною `TELEGRAM_BOT=off`.

Якщо `pnpm start` каже `EADDRINUSE`, десь лишився старий процес:

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN     # подивитись хто
kill $(lsof -t -iTCP:3000 -sTCP:LISTEN)
API_PORT=3001 pnpm start             # або просто інший порт
```

## Коли щось перестало працювати

Перше, що треба перевірити, це чи база не відстала від коду:

```
http://localhost:3000/api/health?deep=1
```

Поле `migrations.behind` більше нуля означає, що код новіший за схему, і сторінки
падатимуть на першій же новій колонці. Лікується `pnpm db:migrate` локально або
`pnpm cf:migrate` на воркері. `pnpm start` і `pnpm dev:api` застосовують міграції самі,
тому відстати можна головним чином на задеплойованому.
